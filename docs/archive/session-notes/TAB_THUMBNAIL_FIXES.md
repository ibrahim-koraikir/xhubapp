# Tab Thumbnail Fixes - Wrong Thumbnails & Quality Issues

## Issues Fixed

### 1. Wrong Thumbnails Showing in Wrong Tabs
**Problem**: User reported "4 tabs thumbnail in tab 1, 3 in tab 2" - thumbnails were showing in the wrong tabs.

**Root Cause**: In `TabsDrawerAdapter.onBindViewHolder()`, the code was using the **position** to fetch the `WebPageTab` from `allTabs`:
```kotlin
val webPageTab = webBrowser.getTabModel().allTabs.getOrNull(position)
```

This caused a mismatch because:
- RecyclerView positions can change when tabs are reordered
- The `TabViewState` has a unique `id` field that should be used instead
- Using position meant tab at position 0 would always get thumbnail from the first tab in the list, regardless of which tab it actually represents

**Solution**: Changed to use the **tab ID** from `TabViewState` to find the correct tab:
```kotlin
val webPageTab = webBrowser.getTabModel().allTabs.find { it.id == tab.id }
```

This ensures the correct thumbnail is always fetched for each tab, regardless of position or reordering.

### 2. Poor Thumbnail Quality
**Problem**: User reported "the quality is bad"

**Previous State**: Thumbnails were captured at 440dp (2x display size)
- Display size: 220dp height
- Capture size: 440dp height (2x)
- Memory per thumbnail: ~580KB
- 20 thumbnails: ~11.6MB

**Solution**: Increased capture resolution to 660dp (3x display size)
- Display size: 220dp height  
- Capture size: 660dp height (3x)
- Memory per thumbnail: ~1.3MB
- 20 thumbnails: ~26MB (still acceptable for TIN tier with 20 tab limit)

This provides significantly better quality while remaining within acceptable memory limits.

## Technical Details

### Why Tab ID Matters
Each `WebPageTab` has a unique ID generated by `View.generateViewId()`. This ID:
- Remains constant throughout the tab's lifetime
- Is independent of the tab's position in the list
- Is stored in both `WebPageTab` and `TabViewState`
- Is used as the key in `TabThumbnailCache`

Using position instead of ID caused thumbnails to be fetched from the wrong tabs because:
1. Tab at position 0 would fetch thumbnail for whatever tab happened to be first in `allTabs`
2. When tabs were reordered, positions changed but IDs remained the same
3. The cache stores thumbnails by ID, but we were fetching tabs by position

### Memory Impact
The increased resolution (2x → 3x) increases memory usage:
- Per thumbnail: 580KB → 1.3MB (2.24x increase)
- 20 thumbnails: 11.6MB → 26MB (2.24x increase)

This is still acceptable because:
- TIN tier (minimum) has 20 tab limit, so max 26MB for thumbnails
- Higher tiers have 10000 tab limit but only cache 20 most recent tabs
- LRU eviction ensures oldest thumbnails are removed when cache is full
- Modern Android devices have sufficient memory for this usage
